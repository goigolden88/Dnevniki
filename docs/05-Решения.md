# Решения

Какие были развилки, что выбрали и почему. Отвечает на вопрос «почему так, а не иначе».
Записывается в момент выбора, чтобы через месяц не переобсуждать заново.

---

### Р-01 · Своё приложение, а не плагины Obsidian
05.09.2026

Dataview и Templater закрыли бы около 70% задачи за дни вместо месяцев. Выбрано своё приложение: цель не только решить задачу, но и построить вещь, плюс Obsidian на телефоне неудобен для быстрого ввода, а быстрый ввод — корень проблемы.

### Р-02 · PWA, не нативная разработка
05.09.2026

Даёт установку иконкой, офлайн и уведомления без сторов и без второй кодовой базы. Ограничение принято: на `file://` service worker не работает, нужен http — локальный сервер или Pages.

### Р-03 · Три модуля, а не один универсальный дневник
05.09.2026

Циклы, эпизоды и потребление требуют разной механики ввода и разной аналитики. Попытка свести их к одному экрану и была причиной, по которой прежняя система казалась бессмысленной.

### Р-04 · Политический дайджест и кешбеки остаются в Obsidian
05.09.2026

Не имеют структуры «событие с датой». Это текст и правила, в событийной модели им плохо.

### Р-05 · Local-first, IndexedDB
05.09.2026

Сеть не должна быть в критическом пути записи, иначе мгновенный отклик — главная фича — умирает. localStorage отвергнут: лимит ~5 МБ и синхронный API, подвешивающий интерфейс на импорте.

### Р-06 · Хранилище данных — GitHub, два репозитория
05.09.2026

Бесплатно, без своего сервера, с историей изменений и откатом, данные в читаемом виде. Публичный репозиторий для кода (Pages для приватного платные, секретов в коде нет), приватный — для данных.

Отвергнуто: свой бэкенд (избыточен для одного пользователя), облачные диски (нет нормального API из браузера).

### Р-07 · Слияние: последняя правка побеждает, по записи
05.09.2026

Изначально рассматривался чистый журнал добавлений, но он не позволяет править и удалять. Выбрано: каждая запись хранит `updatedAt`, при слиянии по `id` берётся более поздняя версия.

Ключевое: сравнение по *записи*, а не по файлу целиком. Иначе запись с телефона затирает запись с компа. Переделывать это потом дорого, поэтому зафиксировано до начала кода.

Удалённые записи остаются метками навсегда — иначе второе устройство их воскресит.

### Р-08 · Нарезка данных по годам
05.09.2026

Иначе каждая отметка переписывает всю базу и раздувает историю коммитов. Прошлые годы после закрытия не трогаются.

### Р-09 · TypeScript
05.09.2026

Проект идёт через много бесед, и без типов модель данных расползётся между сессиями — в новой беседе неизвестно, как назывались поля. Сборка через Vite нужна в любом случае, лишнего шага не появляется.

### Р-10 · Хеш-роутинг
05.09.2026

На GitHub Pages обычные пути дают 404 при обновлении страницы.

### Р-11 · Импорт из Obsidian вручную, парсер не пишем
05.09.2026

Файлов немного, а форматов дат три вперемешку. Содержимое приводится к JSON в отдельной беседе и загружается файлом. Писать парсер под разовую задачу невыгодно.

### Р-12 · Внешние базы контента — необязательная кнопка
05.09.2026

Shikimori, TMDB, RAWG подтягивают обложки и метаданные. Но ручной ввод остаётся основным путём: нет сети или не нашлось — записал руками, ничего не блокируется.

### Р-13 · Физическая активность — в модуль здоровья
05.09.2026

Связь травм и нагрузки — то, что дневник должен показывать. Тип данных третий (сессия с метриками), но модуль тот же. Граница с будущим тайм-менеджером: здесь фиксируется факт, там планируется намерение.

### Р-14 · Замена вещи и процедура — одна структура
05.09.2026

Событие обнуляет счётчик, промежуток между событиями и есть срок службы. Разделять флешку и стрижку незачем, разница только в словах на экране.

### Р-15 · Репозиторий и токен — настройки, а не константы
05.09.2026

Иначе приложением невозможно поделиться. Посторонний получает режим по умолчанию: данные в браузере, синхронизации нет, перенос экспортом. Своя синхронизация — опция для тех, кто заведёт репозиторий и токен.

### Р-16 · Пуши откладываются на поздний этап
05.09.2026

На Android веб-пуши работают нормально и добавляются потом без переделок архитектуры.

## Открытые вопросы

- **Дневник Депры.** Ежедневная шкала, а не эпизоды с началом и концом. Тип данных четвёртый. Решение о включении в приложение не принято.
- **«Ту Бумги» и «Исходров».** Содержание не выяснено, классификация не проведена.
- **Библиотека графиков.** Своё на SVG или готовая. Решается на этапе 3.
