Обновляется в конце каждой беседы. Новые записи сверху.

## 07.09.2026 — Этап 0, каркас

**Сделано**

- Vite 8 + React 19 + TypeScript 7, обычный CSS. `strict` и `noUncheckedIndexedAccess`
- Хеш-роутинг на `react-router-dom`, три экрана: «Сейчас», «Лента», «Настройки»
- Деплой на GitHub Pages через Actions, автоматически при пуше в `main`. В настройках репозитория Source переключён на GitHub Actions
- PWA: манифест, service worker на `vite-plugin-pwa` с `registerType: 'autoUpdate'`, иконки 192/512 и maskable, установка иконкой, работа без сети
- `core/model.ts` — типы из Архитектуры дословно, `SCHEMA_VERSION`, соответствие «хранилище → тип записи», пустой реестр миграций
- `core/db.ts` — обёртка над IndexedDB: 8 синхронизируемых хранилищ, `meta`, `settings`, `dirty`. Мягкое удаление, очередь изменений, слияние по Р-07, экспорт и загрузка слепка
- `core/id.ts` — ULID с монотонностью внутри миллисекунды
- `core/dates.ts` — разбор, формат, разница в днях, русские склонения
- 32 теста на `dates` и `id`

**Состояние**

Приложение открывается на `https://goigolden88.github.io/Dnevniki/`, ставится иконкой, работает без сети. `core` покрыт типами. Модули не начаты — Today и Feed заглушки.

Экран «Настройки» показывает версию схемы, счётчики по хранилищам, очередь на отправку и дату сборки. Дата сборки нужна для проверки, что обновление доехало до телефона.

Проверено: `indexedDB` не упоминается нигде, кроме `core/db.ts`. `npm audit` чистый.

**Находки по ходу**

- В `02-Архитектура.md` `Template.kind` объявлен как `EventKind`, но сам тип нигде не описан. Заполнен пятью значениями (Р-19), документ дописан
- `@vite-pwa/assets-generator` тянет `sharp` с libvips, у которого четыре CVE. Иконки рисует свой скрипт на `zlib` (Р-20)
- Пометка грязных записей уточнена: `db` копит ссылки, файлы из них собирает `sync` (Р-18)

**Не описано в документах — на обсуждение**

- **Хранилище `settings` не описано в Архитектуре.** Сказано только, что настройки хранятся отдельно и не синхронизируются. Состав ключей (репозиторий, токен, предпочтения) не зафиксирован — понадобится на Этапе 2
- **Формат файла экспорта.** `db.exportAll()` отдаёт `{schemaVersion, exportedAt, data}`. В Архитектуре описана раскладка по файлам в репозитории данных, но не формат единого файла для ручного переноса. Это два разных формата, и второй нигде не описан
- **Миграции данных при загрузке файла.** Реестр миграций рассчитан на схему IndexedDB. Файл со старой схемой сейчас отвергается с явной ошибкой — писать миграцию содержимого пока не на чем
- **Что делать при `onblocked`.** Если приложение открыто в двух вкладках, а схема обновилась, вторая вкладка получит ошибку. Сейчас показывается текст «закройте её и обновите страницу». Насколько это годится — вопрос на потом

**Следующий шаг**

Этап 1 — циклы локально. Экран «Сейчас» с позициями по срочности, отметка в один тап, история и медиана интервалов, загрузка стартовых данных из Obsidian.

## 05.09.2026 — Проектирование

**Сделано**

- Разобраны скриншоты дневников из Obsidian, данные классифицированы по типам
- Установлено, что дневники распадаются на три структурно разных типа: циклы, эпизоды, потребление. Единой аналитики для них не существует, отсюда ощущение бессмысленности
- Собран одноразовый прототип модуля циклов (`formular.jsx`) на реальных данных. Показал работоспособность механики: медианные интервалы, статусы, полоса перебора
- Определён полный состав фич по трём модулям и ядру
- Спроектирована архитектура: модель данных, раскладка файлов, механика синхронизации, структура кода
- Заведены документы проекта

**Находки на реальных данных**

- Записи по гигиене обрываются в мае при том, что файл ведётся. Отметки не доезжают в журнал — это и есть основная проблема, которую должно закрыть приложение
- Блок питания type-C куплен дважды за 51 день (02.07 и 22.08.2026). В плоском списке незаметно, в интервалах видно сразу. Либо дубль записи, либо покупается негодное
- Даты записаны в трёх форматах вперемешку: `24.01.26`, `20-02-2026`, `03.03-2026`. Требуется нормализация при переносе

**Состояние**

Код не начат. Прототип `formular.jsx` — иллюстрация, в кодовую базу не идёт.

**Не выяснено**

- Что означают дневники «Ту Бумги» и «Исходров»
- Судьба дневника Депры

**Следующий шаг**

Этап 0 — каркас. Репозитории, сборка, деплой, `core`.
