## 09.09.2026 — Этап 2 закрыт, синхронизация работает

**Сделано**

- `core/github.ts` — клиент GitHub на Git Data API. Одна синхронизация — один коммит, ветка двигается без `force` (Р-32). Ошибки переведены в человеческие: 401 прямо называет истёкший срок токена
- `core/layout.ts` — раскладка записей по файлам и обратно, без сети и без базы. Канонический вид: записи по `id`, ключи по алфавиту. Иначе отпечаток файла каждый раз новый и каждый проход переписывает весь репозиторий
- Р-33: дерево пересобирается из базы целиком, отправляются только файлы с разошедшимся отпечатком. `dirty` больше не выбирает, какие файлы писать — по пометке «запись изменилась» нельзя найти файл, из которого запись уехала при смене года
- Р-34: запись без разбираемого года уезжает в `<модуль>/undated.json`. Закрывает вопрос, висевший с Р-21: 72 записи контента без `start` уже в базе, и класть их куда-то надо сегодня
- `core/sync.ts` — проход целиком, состояние для экрана, запуск по событиям: пять секунд тишины после правки, возврат сети, возврат вкладки, старт приложения
- `db` получил оповещение об изменениях. Он объявляет, что записал, и не знает, кто подписан: так `sync` узнаёт, что пора отправлять, а экран циклов — что приехали чужие записи. Граница «`db` не знает про `sync`» цела
- Настройки синхронизации: репозиторий, ветка, токен, «Проверить доступ». Проверка сразу говорит, приватный ли репозиторий и разрешена ли запись
- Срок жизни токена: из заголовка ответа GitHub либо вписывается руками, предупреждение за 30 дней, отдельный текст ошибки при отказе по токену

- Р-35: заправки и деньги — не сюда. Ремонт и ТО уже описываются циклами, заправка в них не ложится вовсе
- 189 тестов

**Три поломки на живом запуске, все мои**

Ни одна не всплыла в тестах, и это про тесты, а не про везение.

- **Пустой репозиторий.** Git Data API не работает, пока в репозитории нет ни одного коммита: 409 «Git Repository is empty» отвечают и чтение ветки, и создание дерева. Чинилось в два захода — сначала я поправил только чтение, и падать стало на отправке с тем же текстом. Обходной путь взят из документации: первый файл кладётся через Contents API. Мой тест на пустой репозиторий существовал и был зелёным — он проверял мою догадку о поведении GitHub, а не сам GitHub
- **«Синхронизация выключена» при упавшем проходе.** Пустой ответ `syncNow` означал два разных события, а экран знал про одно
- **Настройки читались раньше, чем сохранялись.** Репозиторий и токен писались по потере фокуса, а кнопку жмут тем же движением, каким вставляют токен. Синхронизация видела «токена нет» при заполненных полях. Поймано на первом запуске с телефона. Теперь поля сохраняются по ходу набора, записи выстроены в очередь, кнопка её ждёт

Общее у всех трёх: они лежат ровно там, где тестов нет, — на границе с чужим сервисом и в React. Первая половина закрывается только живым запросом, вторая — jsdom, которого в проекте так и нет.

- **Токен на каждом устройстве свой.** Настройки не синхронизируются, так что телефон получает собственный токен. Лучше выпускать отдельный на устройство: потерянный телефон отзывается, не ломая компьютер. В документах это нигде не сказано

- Отмена ошибочного тапа сделана повторным тапом по той же кнопке: отмечено сегодня → «Отмечено», нажатие снимает отметку. Отдельной отмены на экране нет

- Категория — поле ввода с подсказками, а не список. В модели `cat` — свободная строка, отдельной сущности категории нет
- «Сегодня» пересчитывается при возврате вкладки из фона. Установленное приложение неделями не перезапускается, и дата иначе застывает на дне установки

**Не описано в документах — на обсуждение**

- **Тесты интерфейса.** Ставить ли jsdom и покрывать ли экраны. Сейчас единственная проверка React-части — глаза на телефоне

- **Стоимость владения.** `price` в модели есть, на экранах не показывается. Где ей место — в позиции или в аналитике — не решено

- **Миграции данных при загрузке файла.** Реестр миграций рассчитан на схему IndexedDB. Файл со старой схемой сейчас отвергается с явной ошибкой — писать миграцию содержимого пока не на чем

- **Что делать при `onblocked`.** Если приложение открыто в двух вкладках, а схема обновилась, вторая вкладка получит ошибку. Сейчас показывается текст «закройте её и обновите страницу». Насколько это годится — вопрос на потом
