Как ведётся работа над проектом. Не про то, что строим, а про то, как.

## Где что живёт

| Что | Где |

| Документы проекта | `docs/` в том же репозитории |

Сам README агенты автоматически не читают: Claude Code подхватывает
`CLAUDE.md`, Codex — `AGENTS.md`. Стартовый промпт своей копии в README
поэтому велит прочитать `CLAUDE.md` явно (Р-77).

Документы лежат вместе с кодом, а не в проекте Claude.ai. Причины две: `CLAUDE.md` подхватывается автоматически в каждой сессии, а документы получают версионирование заодно с кодом. Держать их в двух местах нельзя — разъедутся за месяц.

Отсюда правило для бесед в чате: копии в проект Claude.ai кладутся свежие из репозитория и **правятся только в репозитории**. Файл, лежащий в проекте Claude.ai, — снимок, а не документ. Правка, сделанная в снимке, не существует. Надёжнее подключить проект Claude.ai к репозиторию напрямую и убрать ручной перенос совсем.

### Сессии Claude Code

Между этапами — `/clear`, не новая беседа: папка та же, `CLAUDE.md` подхватывается автоматически, сессия начинается со сверки по Журналу и Плану. `/compact` — для середины этапа, когда работа не закончена.

Перед `/clear`: рабочее дерево чистое, всё запушено, и по одному Журналу понятно, где мы и что дальше. Если непонятно — чинится Журнал, а не тащится контекст.

### Подмодуль ядра

Действует с 24.09.2026: «Дневники» переведены на `FamilyCore` коммитом-переездом (Р-81), последними в семье.

- **Клон** — только `git clone --recurse-submodules`; уже склонированное без него — `git submodule update --init`. Иначе `src/shared` пустая и сборка падает непонятной ошибкой
- **`src/shared` отсюда не правится.** Ядру чего-то не хватает, в нём ошибка или `db` и `sync` не подходят под его типы без `as` — сказать человеку, что и где, дать промпт сессии сопровождения `FamilyCore` (шаблон — в её `06-Процесс`) и остановиться. Правка — сессией из корня `FamilyCore`, решением «Я-NN», с тестом на «Полке» и зелёным CI ядра
- **Обновление ядра здесь** — `git submodule update --remote src/shared` (или `git -C src/shared checkout <коммит>`), затем `npm test`, `npm run build`, `npm run smoke` по коду выхода и **коммит указателя**. Забытый указатель — правки нет ни у второго устройства, ни в сборке. Видимое человеку изменение ядра — строка в `src/changes.ts` в том же коммите
- **Перед пушем** — `git status` чистый **и в подмодуле тоже**: `git -C src/shared status`
- **В `src/shared` не запускать `npm install`** — заведётся `src/shared/node_modules` со второй копией React (Я-02 «FamilyCore»)
- **Тесты ядра здесь не гоняются, типы — проверяются** (Р-82): `npm test` — только свои; `tsc` в `npm run build` проверяет `src/shared` целиком. Число тестов с 24.09.2026 — 390, а не 629: механика ушла с ядром. Пропущенный файл при обычном `npm test` один — `realdata.test.ts`, он без копии данных не запускается; другое число пропущенных — файл не загрузился, разбираться
- **Откат** перевода — `git revert` коммита-переезда; откат обновления ядра — указатель на прежний коммит, одна строка в диффе. Точка невозврата — первая миграция схемы поверх ядра (Р-81)
- **Сверять с чужим кодом** — только через `git show` объектов git: рабочие копии развёрнуты в CRLF и врут

## Разделение работы

**Claude Code — и «что строить», и «как» (Р-80).** Состав фич, продуктовые развилки, пересмотры архитектуры — тоже здесь: он видит настоящие файлы и проверяет факты вместо догадок. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой**, для свободного разговора без привязки к коду и для картинок. Его итог приходит в репозиторий потоком ниже.

Прежде продуктовое отдавалось чату: контекст сессии Claude Code забивается файлами, и длинное обсуждение съедает то, что нужно на код. Это снимает `/clear` после планирования — память проекта в документах, а не в сессии.

### Планирование в Claude Code

1. Сессия планирования из корня репозитория — заготовка ниже, в «Шаблонах»
2. Решения — в `05-Решения` в момент выбора; правки `01`, `02`, `03` — по ходу
3. Конец: Журнал, передача в следующую сессию, коммит документов, дерево чистое
4. `/clear` — и код новой сессией по плану

## Поток изменений из чата: чат → документы → код

1. Обсуждаем крупное изменение в чате
2. На выходе получаем **готовые куски markdown для вставки в документы**, а не пересказ беседы. Обычно три:
   - запись в `05-Решения` — развилка, выбор, обоснование
   - правка `01-Проект`, если поменялся состав фич
   - правка `02-Архитектура`, если поменялась модель данных
3. Отдельным пунктом — **что придётся переделать в уже написанном коде**. Без этого Claude Code увидит новую спецификацию и противоречащий ей старый код и будет гадать, что из этого правда
4. Вставляем, коммитим
5. Следующая сессия Claude Code начинается со сверки

Смысл в том, что источник истины — документы в репозитории, а не чья-либо память о беседе.

## Обратный поток: код → чат

Claude Code по ходу работы натыкается на дыры в архитектуре. Если в конце сессии он говорит «вот это в документах не описано» — это возвращается в чат для обсуждения, а не решается на месте. Иначе решения принимаются молча и нигде не фиксируются.

## Правила ведения документов

**Не менять задним числом.** Если решение отменяется, старая запись в `05-Решения` остаётся, новая пишется под новым номером со ссылкой «отменяет Р-07». Иначе через полгода будешь смотреть на код и не понимать, почему он сделан не так, как написано — а причина будет в стёртой записи.

**Решения записываются в момент выбора**, не в конце сессии по памяти.

**Журнал обновляется в конце каждой сессии.** Что сделано, в каком состоянии, следующий шаг.

**Перед пушем — `npm run test` и `npm run smoke`.** Первое проверяет расчёт, второе — что приложение открывается и не падает на обычном пути (Р-41). Тестов экранов в проекте нет, и без прогона React-часть не проверяется ничем, кроме глаз на телефоне через неделю. Итог — по коду выхода и по числу пропущенных тестов, а не `grep`'ом по выводу. И `git -C src/shared status` — чистый.

**Перед пушем миграции — ещё и копия настоящих данных** (Р-72). Свежая копия («Сохранить в файл») кладётся в корень репозитория — `.gitignore` её прячет. `npm run check:data -- <копия>` строит базу той версии, в которой копия сделана, проводит её через миграции и проверяет, что ни одна запись не пропала и всё читается. `npm run smoke -- --data <копия>` обходит на ней все экраны. Пустая база в обычном прогоне миграцию почти не проверяет: данных в ней нет.

**Видимое изменение — строка в `src/changes.ts`**, в том же коммите. Обновления приходят сами и молча; после обновления «Что нового» показывает эти строки (Р-71). Сборка без видимых изменений строки не получает.

**План содержит только предстоящее.** Сделанное переезжает в Журнал.
