# Проект

Обновлён: 11.09.2026

## Зачем

Заменить разрозненные дневники в Obsidian одним приложением, которое не просто хранит записи, а отвечает на вопросы и даёт отклик на каждую запись.

## Проблема

Текущая система — набор markdown-заметок с таблицами и списками дат. Три конкретных изъяна:

1. **Дорогая запись.** Открыть Obsidian, найти файл, найти месяц, вручную написать дату — около 40 секунд на событие ценой в 3 секунды.
2. **Нулевой отклик.** Запись уходит в пустоту, ничего не происходит.
3. **Нет вопроса.** Дневник, который ни на что не отвечает, — архив, а не инструмент.

Следствие: ведение ощущается рутиной без смысла, отметки перестают доезжать в журнал. Проверено на данных — записи по гигиене обрываются в мае при живом файле.

## Что заменяем

| Дневник в Obsidian | Куда идёт |
|---|---|
| Гигиенических предметов | Модуль 1 — Циклы |
| Технических предметов (электроника, водопровод, авто, дача) | Модуль 1 — Циклы |
| Ту Бумги | Не нужен (Р-64) |
| Здоровья | Модуль 2 — Здоровье |
| Развлечений | Модуль 3 — Контент |
| Курсов новых навыков | Модуль 3 — Контент |
| Еды | Отдельное приложение |
| Досуга | Отдельное приложение (тайм-менеджмент) |
| Политический дайджест | Остаётся в Obsidian |
| Оптимизация кешбеков | Остаётся в Obsidian |
| Исходров | Не нужен (Р-64) |
| Депры | Модуль 2 — Здоровье: эпизодами, как болезнь (Р-64) |
| Заметки, быстрые мысли, недельные обзоры | Тайм-менеджер, отдельное приложение (Р-79) |

Политический дайджест и кешбеки не имеют структуры «событие с датой» — это текст и правила. В событийную модель они не ложатся, и тащить их сюда не надо.

## Границы

**Делаем:** три модуля событийных данных, local-first, работа офлайн, синхронизация двух устройств, экспорт без замков.

**Не делаем:** аккаунты, бэкенд, многопользовательский режим, мобильную нативную разработку, парсер markdown-файлов Obsidian.

## Ядро (общее для модулей)

- Быстрый ввод в 2–3 тапа, дата по умолчанию сегодня, у каждой даты кнопка «сегодня» (Р-51), ввод задним числом
- Шаблоны быстрого ввода для отметок циклов: одна кнопка отмечает одну или несколько позиций с ценой, заводится с экрана позиции. Готовых пресетов нет — они не могут знать чужих позиций (Р-49)
- Мгновенный отклик после записи: что изменилось, когда следующий раз
- Главный экран «Сегодня»: просроченное, активные эпизоды, что сейчас смотрю
- Единая лента всех событий с фильтрами и поиском
- Экспорт и импорт JSON, экспорт в markdown
- Работа офлайн, синхронизация в фоне
- Локальные уведомления о просроченном и о незакрытой болезни: без сервера, только Chrome на Android у установленного приложения (Р-50, Р-54)

## Модуль 1 — Циклы

Расходники, процедуры и обслуживание: гигиена, дом, техника, авто, дача.

- Позиции с интервалом: задан вручную либо посчитан как медиана собственной истории
- Статусы: просрочено / подходит к сроку / в норме / нет записей / срок не задан
- Отметка в один тап, история по позиции, разброс интервалов
- Срок службы вещи: промежуток между заменами. Механически то же самое, что процедура
- Цена покупки → суммы потраченного по позиции, кусту и категории (Р-36 отменяет прежнюю «стоимость владения в месяц»: она требует интервала, которого у большинства позиций нет)
- Аналитика: стабильность интервалов, траты на расходники за год

## Модуль 2 — Здоровье

- Эпизод: название, источник диагноза (самодиагностика / врач), начало, конец, симптомы, заметка
- Открытый эпизод без даты окончания — «болею сейчас»
- Симптомы переиспользуемыми тегами, иначе они не анализируются
- Измерения: вес, рост, давление — числовые ряды с графиком
- Физическая активность: сессии с длительностью и дистанцией
- Аналитика: частота за год, средняя длительность, сезонность, промежутки между эпизодами, повторяющиеся симптомы
- Сводка для врача: одна страница хронологии на печать
- Данные только локально и в приватном репозитории

## Модуль 3 — Контент

- Запись: тип (аниме / сериал / фильм / игра / книга / курс), название, начало, конец, статус, оценка, комментарий
- Статус «бросил» обязателен — без него курсы бессмысленно считать
- Список «к просмотру»: статус `planned`, дата начала не задана. Часть этого модуля, не тайм-менеджера — граница «факт vs намерение» здесь про распределение времени, а не про конкретные тайтлы (см. Р-21)
- Аналитика: итоги года, распределение оценок, разбивка по типам, начато против закончено
- «Сейчас смотрю» на главном экране

## Соседние проекты

Приложения по еде и тайм-менеджменту разрабатываются отдельно. Туда же уходят деньги: заправки, страховка, штрафы и кешбеки — это суммы за период, а не события со сроком (Р-35). Ремонт и ТО автомобиля остаются здесь, в циклах: у них есть интервал и «просрочено». Сейчас интеграции нет, но формат событий закладывается общий, чтобы позже слить всё в одну ленту без переделок. Граница с тайм-менеджером: здесь фиксируется факт, там планируется намерение. Туда же уходят заметки и недельный обзор; обзор подтягивает факты недели отсюда (Р-79). Соседние приложения — отдельными репозиториями, а не модулями этого.

## Распространение

Приложение должно работать у постороннего человека без настройки: режим по умолчанию — данные в браузере, без синхронизации, перенос через экспорт файла. Синхронизация — опция для тех, кто заведёт свой приватный репозиторий и токен. Репозиторий и токен обязаны быть настройками, а не константами в коде.

Как поставить и настроить — `docs/07-Установка.md` (Р-76). Как сделать себе свою копию приложения и дорабатывать её, что можно достроить — README (Р-77). Хранилище кроме GitHub не строится, только описано (Р-75).
